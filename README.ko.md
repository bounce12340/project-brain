# 🔷 艾爾水晶(아이우르 크리스털) — 프로젝트 진행 현황

[繁體中文](README.md) | [English](README.en.md) | [简体中文](README.zh-CN.md) | [日本語](README.ja.md) | **한국어**

> 칼라처럼, 팀 모두가 크리스털 안에서 각 프로젝트의 맥박을 함께 느낄 수 있습니다.

**운영 사이트**: <https://projects.uic-ai.com>｜**버전**: v11.2｜**테스트**: 206/206 ✅｜**플랫폼**: Cloudflare Workers

대만 의약품 대리점(UIC) 내부 팀을 위한 프로젝트 진행 현황 공유 플랫폼입니다. 기존에는 추적 업무가 6개의 Excel 파일로 분산되어 BD, RA, QA, 임상 팀이 서로 따로 관리하고 같은 프로젝트를 여러 사람이 중복 기록했습니다. 이제 프로젝트, 진행 현황, OKR, 규제 동향, 라이선스 만료일, 변경 관리를 하나의 크리스털에 모아 전 구성원이 실시간으로 상황을 공유하고, 단계별 권한과 AI 지원, 자동 알림을 활용합니다.

## ✨ 기능 개요

- **프로젝트 관리**: 팀 구분(BD／임상／QA／RA-PV), 3단계 공개 범위(전사／같은 팀／비공개), 같은 팀 구성원 간 입력 지원, 인턴의 제한된 열람 범위, 자동／수동 진행률, 마일스톤, 단계 템플릿
- **4가지 작업 보기**: 칸반(드래그 앤 드롭)｜목록｜달력｜간트(종속성 화살표＋today 선). 작업 서랍에는 `@멘션` 댓글, 첨부 파일, 종속성, AI 요약이 포함됩니다
- **OKR**: 분기 목표＋Key Results(담당자／상태／정렬 순서). 달성률은 자동 진행률에 반영됩니다
- **전용 모듈**: 임상 환자 등록(목표 vs 누적, 일별 등록)｜BD 허가 등록(건별 상태 머신, 이력, 비용)｜QA 라이선스 만료(만료 단계별 경고＋자동 알림)와 CCR 변경 관리(`CCR-YYYY-NNN` 상태 머신＋이력)
- **규제 동향**: 2018년 이후 TFDA 규제 600+건을 담은 지식 베이스로, 공고일순 정렬과 제품군／분류／키워드 필터를 지원합니다. 매일 TFDA RSS를 자동 수집해 검토 대기 초안을 만들고 승인 후에만 전 구성원에게 공개합니다. 공고문을 붙여 넣거나 여러 파일을 함께 업로드하여 AI로 구조화해 가져올 수도 있습니다
- **AI 지원**(Ollama Cloud, deepseek-v4-pro): 진행 기록 빠른 작성, 작업 요약, 프로젝트 위험 예측, 일정 제안, 주간／월간 보고서 자동 생성
- **자동화**: “만약…이면…” 규칙 엔진. 매일 TFDA RSS 수집＋알림, AI 주간 보고서(월요일), AI 월간 보고서(매월 1일)를 위한 3개의 cron이 실행됩니다
- **보고서**: 팀별 주간／월간 보고서 원클릭 생성＋인쇄, CSV 내보내기, 팀별 스윔레인 타임라인
- **계정**: 직접 가입＋Email 인증 코드＋관리자 승인. 관리 권한 이전(공동 관리자／완전 이전)과 마지막 관리자 보호 기능을 제공합니다
- **인터페이스**: StarCraft Protoss 테마(금색＝구조, 파란색＝에너지, 모서리를 깎은 패널, 보호막 진행률 표시줄), 다크／라이트 전환, 번체 중국어／English 전환, 최초 로그인 안내, 글자 크기 전환


```powershell
npm run build

```

품질 검사:

```powershell

```

`.dev.vars`에는 `LLM_API_KEY`와 `AGENTMAIL_API_KEY`만 저장하며 Git에서 무시하도록 설정되어 있습니다. 값을 `wrangler.jsonc`, README, log, commit에 넣으면 안 됩니다.

## ☁️ 배포

```powershell
npx wrangler d1 migrations apply project-brain-db --remote
npx wrangler deploy
```

Secrets는 반드시 `.dev.vars`에서 읽어 stdin으로 Wrangler에 전달해야 하며, 명령 인수나 출력에 포함하면 안 됩니다. 배포 후 `npx wrangler secret list`를 사용해 이름만 표시되는지 확인할 수 있습니다.

**LLM 모델 변경**: `wrangler.jsonc`의 `vars.LLM_MODEL`을 변경합니다(엔드포인트도 바꾸려면 `vars.LLM_BASE_URL`도 변경) → `typecheck`＋`build`＋`deploy`. 시스템은 OpenAI 호환 엔드포인트를 우선 호출하며, `LLM_API_KEY`가 없으면 Workers AI로 fallback합니다.

**사용자 지정 도메인 다시 연결**: 현재 `projects.uic-ai.com`이 연결되어 있습니다. 향후 Worker를 재구축한 뒤 custom domain 연결에 실패하면 먼저 `routes`를 제거하고 workers.dev에 배포한 다음 Dashboard → Workers → project-brain → Settings → Domains & Routes에서 수동으로 추가합니다. 마지막으로 `APP_BASE_URL`을 원래대로 되돌리고 다시 배포합니다.

## ⏰ 일정(UTC cron ↔ 타이베이 시간)

| Cron | 타이베이 시간 | 작업 |
|---|---|---|
| `0 1 * * *` | 매일 09:00 | TFDA RSS를 먼저 수집해 검토 대기 초안을 만든 후 마일스톤／할 일／BD 정체／QA 라이선스 만료／프로젝트 정체／자동 보관 알림과 Email 요약을 처리합니다. 수집 실패는 알림을 중단시키지 않습니다 |
| `30 0 * * 1` | 매주 월요일 08:30 | 지난주의 전사 및 팀별 AI 주간 보고서 |
| `30 0 1 * *` | 매월 1일 08:30 | 지난달의 전사 및 팀별 AI 월간 보고서 |

LLM이 실패해도 데이터만 포함된 보고서를 저장합니다. 미리 생성하는 보고서에서는 비공개 프로젝트를 항상 제외하고 문서 끝에 이를 명시합니다. AgentMail이 설정되지 않은 경우 Email만 건너뛰며 앱 내 알림에는 영향이 없습니다.

## 🔐 계정 및 권한

### 가입 및 승인

직원은 로그인 페이지에서 “계정 신청”을 선택합니다. 이름＋회사 Email＋비밀번호＋팀 → 6자리 Email 인증 코드(15분) → 승인 대기 상태로 진행합니다. 관리자는 “관리 → 가입 신청”에서 역할／팀을 조정하여 승인하거나 거절할 수 있으며, 결과는 메일로 통지됩니다. 승인 전에는 로그인할 수 없습니다. 오용 방지를 위해 동일 Email에는 60초의 코드 재전송 대기 시간, 인증 코드 최대 5회 시도, 동일 IP의 일일 상한을 적용합니다. 관리자가 계정을 직접 생성할 수도 있으며, 최초 로그인 시 비밀번호를 반드시 변경해야 합니다.

### 관리 권한 이전

“관리 → 관리 권한 이전”에서 **공동 관리자**(상대방을 admin으로 승격하고 본인은 그대로 유지) 또는 **완전 이전**(원자적으로 먼저 승격한 후 강등)을 선택합니다. 두 방식 모두 자신의 비밀번호를 다시 입력해야 합니다. 시스템은 API 계층에서 마지막 active admin을 강등하거나 비활성화하지 못하도록 막습니다.

## 📖 일상 사용 안내

### 언어 및 테마(English / Dark‧Light)

**전환 방법**: 내비게이션 바 오른쪽 위에 서로 붙어 있는 두 개의 버튼이 있습니다.

1. “**中／EN**”: 전체 인터페이스를 번체 중국어와 English 사이에서 전환합니다(내비게이션, 버튼, 양식, 도움말 페이지, 안내 둘러보기, 상대 시간이 모두 번역됩니다).
2. “**☀／🌙**”: 다크(Protoss 심우주, 기본값)와 라이트(낮의 신전—따뜻한 아이보리 배경, 금색 구조, 짙은 psi 블루) 테마를 즉시 전환합니다. 차트, 간트, 타임라인, 위험 badge, 보호막 진행률 표시줄의 색상도 함께 바뀌며 깜박임이 없습니다.

**설정 기억 방식**: 설정은 각 브라우저의 localStorage(`AIUR_LANG`／`AIUR_THEME`)에 저장되므로 동료에게 영향을 주지 않습니다. 기기를 바꾸거나 캐시를 지우면 기본값인 “번체 중국어＋다크”로 돌아갑니다.

**번역 범위와 경계**:

- 선택한 언어를 따르는 항목: 인터페이스 문구, `/help` 전체, 최초 안내, 개인용 실시간 AI 출력(진행 기록 빠른 작성, 작업 요약, 위험 예측, 일정 근거).
- 항상 번체 중국어로 유지되는 항목: 사용자가 입력한 데이터(프로젝트 이름, 진행 기록, 댓글, 규제 항목), Email 알림, 조직 주간／월간 보고서, 규제 AI 가져오기 분석 결과.
- 인쇄는 항상 흰색 배경을 사용하며 테마의 영향을 받지 않습니다.

### 프로젝트, 작업 및 자동 진행률

1. “프로젝트 → 새 프로젝트”에서 팀, 공개 범위, 목표일, 단계 템플릿을 설정합니다.
2. “개요”에서 수동／자동 진행률을 전환할 수 있습니다. 자동 모드＝작업＋마일스톤＋연결된 할 일＋KR의 완료 비율이며, 새 프로젝트는 자동이 기본값입니다.
3. “작업”에서 4가지 보기를 자유롭게 전환합니다. 칸반에서는 단계와 카드를 드래그할 수 있습니다. 작업을 선택해 서랍을 열면 내용, 담당자, 시작／종료일, 종속성을 편집하고 `@멘션` 댓글, 첨부 파일, AI 요약을 사용할 수 있습니다.
4. “진행 기록”에 메모를 붙여 넣고 “AI 빠른 작성”으로 3단 구성의 초안을 만든 뒤 확인하여 게시합니다.

### 파일, 자동화 및 AI

- 파일은 R2에 저장합니다(파일당 25 MB). 다운로드 시 권한을 확인하며 업로더／owner／admin이 삭제할 수 있습니다.
- “자동화” 규칙: 작업 완료／단계로 이동／마일스톤 완료／진행률이 임계값을 넘음 → 알림／담당 변경／할 일 생성／기록 작성.
- 프로젝트 개요의 “AI 위험 예측”은 등급＋제안을 저장해 대시보드에 표시합니다. “AI 일정 제안”은 백엔드 검증(날짜가 프로젝트 범위 안에 있고 종속성을 위반하지 않음)을 통과해야만 적용할 수 있습니다.

### 규제 동향 AI 가져오기

공고문을 붙여 넣거나 최대 5개의 `.txt`／텍스트 레이어가 있는 `.pdf`를 함께 업로드합니다(파일당 10 MB, 총 25 MB). **단일 공고**(기본값): 전체 묶음 → 1건, **복수 공고 모음**: 공고일 또는 공고 제목이 다른 경우에만 분리합니다.

`entry_date`에는 항상 공고일／발문일을 사용하고 시행일／발효일은 사용하지 않습니다. 시행일은 요약 뒤 첫 번째 핵심 항목에 넣습니다. AI가 추출한 날짜가 오늘보다 90일 넘게 미래이면 미리 보기에서 경고색으로 알리지만 편집이나 가져오기를 차단하지 않습니다. “대조표／개정 조문／현행 조문”이 포함된 자료에는 “개정 핵심(전후 비교)”을 별도로 표시하고, 최대 10개의 “이전 규정→새 규정” 요약을 제공합니다.

미리 보기에서는 각 셀을 편집하거나 제외할 수 있으며, 확정할 때 `(entry_date, title)`로 중복을 판정합니다. 모든 원본 파일은 R2에 저장하고 목록에 `📎×N`을 표시하며 파일별로 다운로드할 수 있습니다. 마지막 참조 항목을 삭제하면 D1 연결과 R2의 고아 객체도 함께 제거합니다. 텍스트 레이어가 없는 스캔 PDF는 텍스트를 붙여 넣어야 합니다(OCR은 의도적으로 지원하지 않습니다).

### TFDA RSS 자동 수집 및 검토

매일 09:00의 사전 작업에서 TFDA 공고 RSS를 읽습니다. RA/PV 정규 직원과 admin은 규제 동향에서 “지금 TFDA 수집”을 선택할 수도 있습니다. 시스템은 기존 TFDA news id, 거절 툼스톤, `(공고일, 제목)`의 3단계 중복 제거를 거쳐 공고 전문(표의 행 포함)을 기존 단일 공고 AI 파이프라인으로 정리합니다. AI가 일시적으로 실패해도 “기타” 분류와 원문 앞 500자로 초안을 만들어 공고가 누락되지 않게 합니다.

새 데이터는 항상 `TFDA 초안`으로 생성되며 검토자에게 앱 내 알림을 보내고 매일의 Email digest에도 포함합니다. 관리 권한이 있는 사용자는 “검토 대기 N”을 선택해 핵심 내용 전문을 펼치고, 편집(초안 상태 유지), 개별 승인／삭제, 선택한 여러 항목의 일괄 승인／삭제 또는 확인 후 전체 승인을 할 수 있습니다. 다른 member와 모든 intern에게는 승인 전까지 전혀 보이지 않습니다. 승인된 후에만 일반 published 목록에 들어갑니다. TFDA 초안이나 게시된 항목을 삭제할 때는 먼저 source ref 묘비를 남겨 이후 cron이 같은 공고를 다시 만들지 못하게 하며, 수동 항목은 영향을 받지 않습니다. 운영 및 인수 테스트 중에는 업무 담당자를 대신해 실제 TFDA 초안을 승인하거나 삭제하면 안 됩니다.

### 보고서 및 타임라인

- “보고서 → 보고서 생성”: 팀＋(이번 주／지난주／이번 달／지난달)을 선택해 한 번에 생성하고 인쇄할 수 있습니다. member는 자기 팀으로 제한되며, admin은 전사 또는 비공개 프로젝트를 포함하는 버전을 선택할 수 있습니다.
- “타임라인”: 팀별 스윔레인에서 볼 수 있는 모든 프로젝트를 한눈에 확인하며, 행을 펼치면 작업 기간 막대(담당자 tooltip)가 표시됩니다.

### 팀 및 단계 템플릿(관리자)

“관리 → 팀”의 유형(`clinical`／`bd`／`qa`／`general`)에 따라 전용 모듈이 결정됩니다. 참조 중인 팀은 삭제할 수 없습니다. “단계 템플릿”에서는 `→`로 단계를 구분합니다. 적용할 때 복사되므로 나중에 템플릿을 수정해도 기존 프로젝트에는 영향을 주지 않습니다.

## 🧭 개발 방식

이 프로젝트는 **명세 기반＋2 agent 파이프라인**을 사용합니다. Claude(명세 작성, 작업 배정, 독립 검수)＋ OpenAI Codex(구현, 배포, E2E 자체 검증)로 구성됩니다. 각 버전에는 서면 명세(`SPEC*.md`)와 명령 및 원본 결과를 사실대로 기록한 검수 파일(`ACCEPTANCE*.md`)이 있습니다. 실패와 미완료 항목은 반드시 기록에 남기며 감추지 않습니다. 구현 결정은 [DECISIONS.md](DECISIONS.md)에 모아 둡니다.
