# 🔷 艾爾水晶（アイウル・クリスタル）— プロジェクト進捗

[繁體中文](README.md) | [English](README.en.md) | [简体中文](README.zh-CN.md) | **日本語** | [한국어](README.ko.md)

> カーラのように、チーム全員が水晶を通じて各プロジェクトの鼓動をともに感じられます。

**本番サイト**：<https://projects.uic-ai.com>｜**バージョン**：v11.2｜**テスト**：206/206 ✅｜**プラットフォーム**：Cloudflare Workers

台湾の医薬品代理店（UIC）社内チーム向けに開発された、プロジェクト進捗共有プラットフォームです。従来は 6 つの Excel ファイルに追跡業務が分散し、BD・RA・QA・臨床がそれぞれ個別に管理していたため、同じプロジェクトを複数人が重複して記録していました。本プラットフォームでは、プロジェクト、進捗、OKR、規制情報、ライセンス有効期限、変更管理を一つの水晶に集約し、全員でのリアルタイムな状況共有、段階的な権限管理、AI 支援、自動リマインダーを実現します。

## ✨ 機能概要

- **プロジェクト管理**：チーム区分（BD／臨床／QA／RA-PV）、3 段階の公開範囲（全社／同一チーム／非公開）、同一チーム内での相互入力支援、インターン向けの閲覧制限、自動／手動進捗、マイルストーン、フェーズテンプレート
- **タスクの 4 ビュー**：カンバン（ドラッグ＆ドロップ）｜リスト｜カレンダー｜ガント（依存関係の矢印＋today ライン）。タスクドロワーには `@メンション` 付きコメント、添付ファイル、依存関係、AI 要約を備えています
- **OKR**：四半期目標＋Key Results（担当者／ステータス／並び順）。達成度は自動進捗に反映されます
- **専用モジュール**：臨床症例登録（目標 vs 累計、日次登録）｜BD 承認申請（案件ステートマシン、履歴、費用）｜QA ライセンス有効期限（期限別アラート＋自動通知）および CCR 変更管理（`CCR-YYYY-NNN` ステートマシン＋履歴）
- **規制情報**：2018 年以降の TFDA 規制 600+ 件を収録したナレッジベースです。公告日順に並び、製品ライン／カテゴリ／キーワードで絞り込めます。TFDA RSS を毎日自動取得してレビュー待ちの下書きを作成し、承認後に初めて全員へ公開します。公告テキストの貼り付けや複数ファイルの一括アップロードによる、AI を使った構造化インポートにも対応しています
- **AI 支援**（Ollama Cloud、deepseek-v4-pro）：進捗のクイック作成、タスク要約、プロジェクトリスク予測、スケジュール提案、週報／月報の自動生成
- **自動化**：「もし…なら…」ルールエンジン。毎日の TFDA RSS 取得＋リマインダー、AI 週報（月曜日）、AI 月報（毎月 1 日）の 3 本の cron を実行します
- **レポート**：チーム別の週報／月報をワンクリックで生成して印刷、CSV エクスポート、チーム別スイムレーンのタイムライン
- **アカウント**：セルフ登録＋Email 認証コード＋管理者承認。管理権限の移管（共同管理者／完全移管）と最終管理者の保護機能
- **インターフェース**：StarCraft の Protoss テーマ（金＝構造、青＝エネルギー、角を落としたパネル、シールド進捗バー）、ダーク／ライト切り替え、繁体字中国語／English 切り替え、初回ログイン時のガイド、文字サイズ切り替え

`.dev.vars` には `LLM_API_KEY` と `AGENTMAIL_API_KEY` だけを保存し、Git の管理対象から除外しています。値を `wrangler.jsonc`、README、log、commit に含めてはいけません。

## ☁️ デプロイ

```powershell
npx wrangler d1 migrations apply project-brain-db --remote
npx wrangler deploy
```

Secrets は必ず `.dev.vars` から読み取り、stdin 経由で Wrangler に渡します。コマンド引数や出力に含めてはいけません。デプロイ後は `npx wrangler secret list` で名前だけが表示されることを確認できます。

**LLM モデルの変更**：`wrangler.jsonc` の `vars.LLM_MODEL` を変更します（エンドポイントも変更する場合は `vars.LLM_BASE_URL` も変更）→ `typecheck`＋`build`＋`deploy`。システムは OpenAI 互換エンドポイントを優先して呼び出し、`LLM_API_KEY` が存在しない場合は Workers AI に fallback します。

**カスタムドメインの再設定**：現在は `projects.uic-ai.com` を設定済みです。将来 Worker を再構築して custom domain の設定に失敗した場合は、まず `routes` を削除して workers.dev にデプロイし、Dashboard → Workers → project-brain → Settings → Domains & Routes で手動追加します。最後に `APP_BASE_URL` を元に戻して再デプロイします。

## ⏰ スケジュール（UTC cron ↔ 台北時間）

| Cron | 台北時間 | 処理 |
|---|---|---|
| `0 1 * * *` | 毎日 09:00 | 先に TFDA RSS を取得してレビュー待ちの下書きを作成し、その後マイルストーン／ToDo／BD 停滞／QA ライセンス有効期限／プロジェクト停滞／自動アーカイブのリマインダーと Email 集約を実行します。取得に失敗してもリマインダーは中断しません |
| `30 0 * * 1` | 毎週月曜日 08:30 | 前週分の全社およびチーム別 AI 週報 |
| `30 0 1 * *` | 毎月 1 日 08:30 | 前月分の全社およびチーム別 AI 月報 |

LLM が失敗しても、データのみのレポートを保存します。事前生成するレポートからは非公開プロジェクトを必ず除外し、末尾にその旨を記載します。AgentMail が未設定の場合は Email 送信だけをスキップし、アプリ内通知には影響しません。

## 🔐 アカウントと権限

### 登録と承認

従業員はログインページで「アカウント申請」を選びます。氏名＋会社 Email＋パスワード＋チーム → 6 桁の Email 認証コード（15 分）→ 承認待ちへ進みます。管理者は「管理 → 登録申請」で承認（ロール／チームの調整も可能）または却下し、結果をメールで通知します。承認前はログインできません。不正利用対策として、同一 Email のコード送信は 60 秒間隔、認証コードの試行は最大 5 回、同一 IP には 1 日あたりの上限を設けています。管理者がアカウントを直接作成することもでき、初回ログイン時にはパスワード変更が必須です。

### 管理権限の移管

「管理 → 管理権限の移管」では、**共同管理者**（相手を admin に昇格し、自分はそのまま）または**完全移管**（アトミックに昇格後、降格）を選べます。どちらも自分のパスワードを再入力する必要があります。システムは API レイヤーで、最後の active admin の降格／無効化を防止します。

## 📖 日常操作ガイド

### 言語とテーマ（English / Dark‧Light）

**切り替え方法**：ナビゲーションバー右上に、隣り合った 2 つのボタンがあります。

1. 「**中／EN**」：インターフェース全体を繁体字中国語と English の間で切り替えます（ナビゲーション、ボタン、フォーム、ヘルプページ、ガイドツアー、相対時間をすべて翻訳します）。
2. 「**☀／🌙**」：ダーク（Protoss の深宇宙、デフォルト）とライト（昼の神殿—温かみのあるアイボリーの背景、金の構造、深い psi ブルー）を即座に切り替えます。チャート、ガント、タイムライン、リスク badge、シールド進捗バーも同時に配色が変わり、切り替え時にちらつきません。

**設定の記憶方法**：設定は各ブラウザーの localStorage（`AIUR_LANG`／`AIUR_THEME`）に保存されるため、同僚には影響しません。端末を替えた場合やキャッシュを消去した場合は、デフォルトの「繁体字中国語＋ダーク」に戻ります。

**翻訳範囲と境界**：

- 選択言語に従うもの：インターフェースのテキスト、`/help` 全文、初回ガイド、個人向けのリアルタイム AI 出力（進捗のクイック作成、タスク要約、リスク予測、スケジュール理由）。
- 常に繁体字中国語のもの：ユーザーが入力したデータ（プロジェクト名、進捗、コメント、規制情報）、Email 通知、組織の週報／月報、規制情報の AI インポート解析結果。
- 印刷時は常に白い背景となり、テーマの影響を受けません。

### プロジェクト、タスク、自動進捗

1. 「プロジェクト → 新規プロジェクト」でチーム、公開範囲、目標日、フェーズテンプレートを設定します。
2. 「概要」で手動／自動進捗を切り替えられます。自動モード＝タスク＋マイルストーン＋関連 ToDo＋KR の完了率です（新規プロジェクトは自動がデフォルトです）。
3. 「タスク」では 4 つのビューを自由に切り替えられます。カンバンではフェーズとカードをドラッグできます。タスクを選択するとドロワーが開き、内容、担当者、開始／終了日、依存関係を編集できるほか、`@メンション` 付きコメント、添付ファイル、AI 要約を利用できます。
4. 「進捗記録」にメモを貼り付けて「AI クイック作成」で 3 部構成の下書きに整え、確認してから公開します。

### ファイル、自動化、AI

- ファイルは R2 に保存します（1 ファイル 25 MB）。ダウンロード時には権限を確認し、アップロードした本人／owner／admin が削除できます。
- 「自動化」ルール：タスク完了／フェーズへ移動／マイルストーン完了／進捗がしきい値を超える → 通知／担当変更／ToDo 作成／記録の追加。
- プロジェクト概要の「AI リスク予測」はレベル＋提案を保存し、ダッシュボードに表示します。「AI スケジュール提案」はバックエンドの検証（日付がプロジェクト内に収まり、依存関係に違反しないこと）を通過した場合のみ適用できます。

### 規制情報の AI インポート

公告テキストを貼り付けるか、最大 5 個の `.txt`／テキストレイヤー付き `.pdf` をまとめてアップロードします（1 ファイル 10 MB、合計 25 MB）。**単一公告**（デフォルト）：全内容 → 1 件、**複数公告の集約**：公告日または公告タイトルが異なる場合に限り分割します。

`entry_date` には必ず公告日／発文日を使用し、施行日／発効日は使用しません。施行日は要約後の最初の箇条書きに記載します。AI が抽出した日付が今日から 90 日を超える未来の日付である場合、プレビューでは警告色を表示しますが、編集やインポートは妨げません。「対照表／改正条文／現行条文」を含む資料には「改正の要点（新旧対照）」を別途設け、最大 10 件の「旧規定→新規定」要約を示します。

プレビューはセル単位で編集／除外でき、確定時に `(entry_date, title)` で重複を判定します。すべての元ファイルを R2 に保存し、リストには `📎×N` を表示してファイルごとにダウンロードできます。最後の参照を削除すると、D1 の関連付けと R2 の孤立オブジェクトも同時に削除します。テキストレイヤーのないスキャン PDF は、テキストを貼り付けてください（OCR は意図的に実装していません）。

### TFDA RSS の自動取得とレビュー

毎日 09:00 の前処理で TFDA 公告 RSS を読み取ります。RA/PV の正社員と admin は、規制情報で「TFDA を今すぐ取得」を選ぶこともできます。既存の TFDA news id、却下済みのトゥームストーン、`(公告日, タイトル)` の 3 段階で重複を排除し、公告全文（表の行を含む）を既存の単一公告 AI パイプラインで整理します。AI が一時的に失敗しても、「その他」と原文の先頭 500 文字で下書きを作成するため、公告を取りこぼしません。

新しいデータは必ず `TFDA 下書き` として作成され、レビュー担当者へのアプリ内通知と毎日の Email digest に含まれます。管理権限を持つユーザーは「レビュー待ち N」を選択して要点の全文を展開し、編集（下書きのまま）、個別の承認／削除、選択した複数件の一括承認／削除、または確認後の全件承認を行えます。その他の member とすべての intern には、承認されるまで一切表示されません。承認後に初めて通常の published リストに入ります。TFDA 下書きまたは公開済み項目を削除する際は、先に source ref の墓石を残して、後続の cron が同じ公告を再作成しないようにします。手動項目には影響しません。運用時および受け入れテスト時に、業務担当者に代わって実際の TFDA 下書きを承認または削除してはいけません。

### レポートとタイムライン

- 「レポート → レポート生成」：チーム＋（今週／先週／今月／先月）を選ぶとワンクリックで生成でき、印刷にも対応します。member は自チームに限定され、admin は全社または非公開プロジェクトを含む版を選べます。
- 「タイムライン」：チーム別スイムレーンですべての閲覧可能なプロジェクトを一覧し、行を展開するとタスクの期間バー（担当者 tooltip）が表示されます。

### チームとフェーズテンプレート（管理者）

「管理 → チーム」のタイプ（`clinical`／`bd`／`qa`／`general`）によって専用モジュールが決まります。参照中のチームは削除できません。「フェーズテンプレート」では `→` でフェーズを区切ります。適用時にコピーされるため、その後テンプレートを変更しても既存プロジェクトには影響しません。

## 🧭 開発モデル

本プロジェクトでは、**仕様駆動＋2 agent パイプライン**を採用しています。Claude（仕様作成、作業割り当て、独立した検収）＋ OpenAI Codex（実装、デプロイ、E2E 自己検証）という構成です。各バージョンには書面の仕様（`SPEC*.md`）と、コマンドおよびその生の結果を正確に記録した検収ファイル（`ACCEPTANCE*.md`）があります。失敗や未達成項目は必ず記録に残し、取り繕いません。実装上の判断は [DECISIONS.md](DECISIONS.md) に集約しています。
